# AGENTS — AI assistant instructions for TheCount

Purpose
- Short, actionable guidance for AI coding assistants working on this repository.

Quick setup
- Create and activate a virtualenv: `python -m venv .venv && source .venv/bin/activate`
- Install dependencies: `pip install -r requirements.txt` (or use the `bot` script from `pyproject.toml` if packaging)
- This project expects two config files in the user's home directory:
  - `~/.countingv2/config.yml` — contains `bot_config` (including `db` credentials and `bot` settings)
  - `~/.countingbotv2/count.json` — optional per-repo count settings

How to run locally
- Start the bot: `python bot.py`
- The code reads DB credentials from `Cfg().bot_config.db` and will attempt to connect on startup. Ensure the DB is reachable before running.

Key files and areas
- [bot.py](bot.py) — entry point and extension loader.
- [config.py](config.py) — reads config from the user's home directory.
- [db.py](db.py) — database and settings helper functions (see Pitfalls).
- [models/](models/) — SQLAlchemy models; `models/base.py` builds the engine using `Cfg().bot_config.db`.
- [cogs/](cogs/) — Discord command/cog implementations (primary extension points).

Conventions for AI agents
- Keep changes small and focused: one behavioral fix or feature per PR.
- Link to existing docs instead of copying them. See [README.md](README.md).
- Avoid committing secrets: do not add tokens, passwords, or full DB connection strings to the repo.
- When editing code that touches configuration or the DB, ensure local config files exist or mock them in tests.

Pitfalls and notes
- `config.py` loads configuration from `~/.countingv2/config.yml` and will `sys.exit(1)` if missing — running code in CI or local dev requires providing these files or stubbing them.
- `models/base.py` constructs the DB connection string at import time and prints it; be mindful of credentials being logged during import.
- `db.py` currently contains structural issues (methods defined under the `ChannelNotFoundError` class and several module-level functions that accept `self`): be cautious when editing this file — prefer small, well-tested refactors.
- SQLAlchemy version here is a beta release (`sqlalchemy==2.1.0b1` in `requirements.txt`) — be conservative when upgrading without tests.
